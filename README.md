# okinawa-itfes-counter

沖縄ビジネスITフェスの受付カウンターを、Windows・Apple・Android の3プラットフォームで作るためのリポジトリ。

実装は下の依頼文に従う。途中で質問せず、迷った点は自分で決めて Pull Request の説明に書く。動作確認の録画を PR に添付する。

各実装PRは担当フォルダの中だけを変更する。リポジトリ直下のファイル（README.md など）は作らない・変えない。.gitignore などが必要なら各フォルダ内に置く。共通仕様を更新する場合は、実装PRと分けた README.md 専用PRにする。

## 共通仕様

- アプリ名は「沖縄ビジネスITフェス受付カウンター」
- 画面に来場者数と、定員50席に対する割合（%）を表示する
- 「来場者+1」を押すたびに1人増える
- 50人を超えたら、割合の横に赤字で「定員オーバー」と表示する
- 「リセット」で0人に戻す
- 「来場者+1」を5回押し、表示が「5人・10%」になることを確かめる

### 来場者アンケート

- カウンター画面に「アンケート」と「集計」ボタンを追加し、各画面から「カウンターに戻る」で戻れるようにする。画面の移動・回答の保存で来場者数は変えない。
- 次の3問をすべて単一選択・必須とし、初期状態は未選択にする。氏名・連絡先・自由記述は収集しない。
  - 満足度: 「1 とても不満」「2 不満」「3 普通」「4 満足」「5 とても満足」
  - 来場のきっかけ: 「SNS」「Webサイト」「知人・同僚の紹介」「チラシ・ポスター」「その他」
  - 年代: 「10代以下」「20代」「30代」「40代」「50代」「60代以上」「回答しない」
- 全問選択するまで「回答を保存」は無効。保存中は重複送信を防ぐ。成功後は「回答を保存しました」と表示し、入力を未選択へ戻して次の来場者が回答できるようにする。未保存で戻った入力は破棄する。
- 回答は通信せず端末内のアプリ専用領域の `survey-responses.json` にUTF-8 JSONで保存する。形式は `{"schemaVersion":1,"responses":[{"id":"UUID","submittedAt":"ISO 8601 UTC","satisfaction":5,"discovery":"sns","ageGroup":"20s"}]}` とする。
  - `satisfaction`: 1〜5の整数。`discovery`: 上記表示順に `sns` / `website` / `referral` / `poster` / `other`。`ageGroup`: 上記表示順に `under20` / `20s` / `30s` / `40s` / `50s` / `60plus` / `no_answer`。
  - 保存先はWindowsではLocalApplicationData配下、AppleではApplication Support配下、Androidでは内部ストレージのfilesDir配下とする。各アプリ・端末のデータは独立し、同期・送信はしない。
  - 一時ファイルからの置換などOS標準機能で原子的に保存し、保存成功後だけ集計へ反映する。失敗時はエラーと再試行手段を表示し、入力と既存データを保持する。
  - ファイルがない初回だけ空の回答として扱う。読み込み失敗・不正JSON・未対応バージョン・不正な回答値はエラーとして通知し、既存ファイルを空で上書きしない。読み直せるまで回答保存を止め、カウンターは利用可能にする。
- 「集計」画面には保存済みの総回答数と、3問それぞれの全選択肢の回答数を表示する（0件の選択肢も表示）。未回答の初回は「回答はまだありません」と各0件を表示する。再起動後も保存済み回答を読み込んで同じ集計を表示する。
- 既存の「リセット」は来場者数だけを0に戻し、アンケート回答は削除しない。回答削除・編集・エクスポートは今回の対象外。
- 各対象OSで入力→保存→集計→アプリ再起動後の集計保持を確認し、操作を録画する。未選択では保存できないこと、カウンターの「5人・10%」、40人・50人・51人の色と警告、リセット後も回答が残ることも確認する。

## 見た目

- 沖縄の海をイメージした、濃い青からエメラルドへのグラデーション背景
- 中央に角丸で影のある白いカード。来場者数は画面でいちばん大きな太字
- 割合は数字に加えてプログレスバー（またはリング）でも表示。通常は緑、40人以上はオレンジ、50人超は赤
- 「来場者+1」は大きく目立つ塗りボタン、「リセット」は控えめな枠線ボタン
- 数字が変わるときに軽いアニメーション
- 外部ライブラリ・画像・フォントは使わず、標準機能だけで作る
- 表示の文言（「5人」「10%」「定員オーバー」）は変えない
- アンケート・集計も同じ海色の背景と角丸・影の白いカードを使う。質問・選択肢・選択状態を明瞭にし、小さい画面では縦スクロールで全項目とボタンに到達できるようにする。
- 「アンケート」「集計」はカウンターの主操作より控えめに配置する。「回答を保存」は塗りボタン、「カウンターに戻る」は控えめなボタンとし、無効状態・成功・エラーを文字でも示す。
- WPF / SwiftUI / Android SDK・Jetpack Composeなど指定フレームワークの標準機能のみを使用し、追加のUI・グラフ・保存ライブラリ、外部画像・外部フォントは使用しない。

## まとめて送る場合（親セッション用の依頼文）

Devinの親セッション（コーディネーター）に、下の依頼文を1回だけ送る。親セッションが①〜④を子セッション（managed Devin）に1つずつ任せて、同時に進める。子セッションが立ち上がらないときは、①〜③は上の依頼文を、④は下の「子セッション④」のブロックを、それぞれ別のセッションで送る。

```text
あなたは今日のコーディネーターです。次の4つの仕事を、それぞれ別の子セッション（managed Devin）に1つずつ任せて、4つ同時に進めてください。あなた自身は実装せず、子セッションの立ち上げ・見守り・最後のまとめだけを担当してください。

【全体のルール】
・①〜③には来場者アンケート（3問の入力・端末内JSON保存・選択肢別集計）も実装し、既存カウンターの動作を変えず、保存と再起動後の保持まで録画してください。共通仕様の更新は別のREADME専用PRで行い、実装PRは担当フォルダ内だけを変更してください。④はアンケート追加の対象外です。
・4つの子セッションは、この送信のあとすぐ、同時に立ち上げてください。
・各子セッションには、下の依頼文をそのまま渡してください。勝手に要約したり、仕様を変えたりしないでください。
・動かす環境は、①はWindows、②と④はmacOS、③はAndroidエミュレーターが使える環境を指定してください。
・子セッションにも私にも質問を戻さず、迷ったところは各自で決めてPRの説明に書かせてください。
・①〜③は同じリポジトリ okinawa-itfes-counter で作業します。それぞれ担当フォルダの外は触らないので、PRどうしはぶつかりません。もしぶつかりそうなら、あなたが調整してください。
・PRはマージしないでください。
```
